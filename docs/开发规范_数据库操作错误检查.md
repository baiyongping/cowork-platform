# 云开发数据库操作错误检查规范

## 问题来源

2025-12-26 发现的生产问题：在 `product_order_forecast` 集合不存在时，`add()` 操作返回错误对象而非成功结果，但代码未检查错误，导致静默失败和死循环。

## 强制规范

### ❌ 错误示例：不检查返回值

```typescript
// 危险：未检查 addResult 是否为错误对象
const addResult = await db.collection('some_collection').add(data);
const recordId = addResult.id; // 可能为 undefined
```

### ✅ 正确示例：必须检查错误

```typescript
// 方案1：检查 code 字段（推荐）
const addResult = await db.collection('some_collection').add(data);
if (addResult.code) {
  console.error('❌ 数据库操作失败:', addResult.message);
  throw new Error(`数据库操作失败: ${addResult.message} (${addResult.code})`);
}
const recordId = addResult.id || addResult._id;

// 方案2：使用 try-catch
try {
  const addResult = await db.collection('some_collection').add(data);
  if (addResult.code) {
    throw new Error(`${addResult.message} (${addResult.code})`);
  }
  const recordId = addResult.id || addResult._id;
  console.log('✅ 记录创建成功，ID:', recordId);
} catch (error) {
  console.error('❌ 数据库操作失败:', error);
  // 用户友好的错误提示
  throw new Error('保存数据失败，请重试或联系管理员');
}
```

## 常见错误码

| 错误码 | 说明 | 解决方案 |
|--------|------|----------|
| `DATABASE_COLLECTION_NOT_EXIST` | 集合不存在 | 先创建集合或使用 MCP 工具检查 |
| `DATABASE_PERMISSION_DENIED` | 权限不足 | 检查安全规则配置 |
| `DATABASE_REQUEST_TIMEOUT` | 请求超时 | 检查网络连接，考虑分批操作 |
| `DATABASE_DUPLICATE_KEY` | 唯一索引冲突 | 检查数据唯一性 |

## 开发流程

### 1. 开发阶段：确保集合存在

```typescript
// 在初始化时检查集合是否存在
async function ensureCollectionExists(collectionName: string) {
  try {
    // 尝试查询集合（如果不存在会返回错误）
    const result = await db.collection(collectionName).limit(1).get();
    if (result.code === 'DATABASE_COLLECTION_NOT_EXIST') {
      console.warn(`⚠️  集合 ${collectionName} 不存在，请在控制台创建`);
      return false;
    }
    return true;
  } catch (error) {
    console.error(`检查集合失败:`, error);
    return false;
  }
}

// 使用示例
const exists = await ensureCollectionExists('product_order_forecast');
if (!exists) {
  throw new Error('数据库集合未创建，请联系管理员');
}
```

### 2. 生产阶段：优雅降级

```typescript
async function saveWithFallback(data: any) {
  try {
    const result = await db.collection('some_collection').add(data);
    if (result.code) {
      throw new Error(result.message);
    }
    return { success: true, id: result.id || result._id };
  } catch (error) {
    console.error('保存失败:', error);
    // 可以选择：
    // 1. 存储到 localStorage 作为草稿
    // 2. 提示用户稍后重试
    // 3. 发送错误报告
    return { success: false, error: String(error) };
  }
}
```

## 代码审查清单

在提交涉及数据库操作的代码前，必须检查：

- [ ] 所有 `add()` 操作后都检查了返回值的 `code` 字段
- [ ] 所有 `update()` 操作后都检查了 `updated` 数量
- [ ] 所有 `remove()` 操作后都检查了 `deleted` 数量
- [ ] 所有查询操作都用 try-catch 包裹
- [ ] 错误信息对用户友好（不暴露技术细节）
- [ ] 关键操作有日志记录（成功和失败都要记录）

## 工具支持

使用 MCP 工具检查集合状态：

```typescript
// 使用 readNoSqlDatabaseStructure 检查集合是否存在
import { call_tcb_integration } from '@/tools';

const result = await call_tcb_integration({
  toolName: 'readNoSqlDatabaseStructure',
  arguments: JSON.stringify({
    action: 'listCollections'
  })
});

// 检查集合是否在列表中
const collections = result.data;
const exists = collections.some(c => c.name === 'product_order_forecast');
```

## 总结

**永远不要假设数据库操作会成功！**

1. **必须检查** 返回值是否包含错误码
2. **必须记录** 错误信息到控制台
3. **必须提供** 用户友好的错误提示
4. **必须考虑** 错误发生后的降级方案
