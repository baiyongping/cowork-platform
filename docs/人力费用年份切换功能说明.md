# 人力费用预算 - 年份切换功能说明

## 📋 功能概述

人力费用预算模块已**完全支持**不同年份建立不同的预算数据。每个年份的数据完全独立存储和管理。

## ✅ 已实现功能

### 1. **数据隔离**
- 每个年份的数据独立存储在CloudBase数据库
- 数据查询时按 `year` 字段进行筛选
- 不同年份的数据互不影响

### 2. **年份切换**
- 在预算管理页面顶部可以切换年份
- 切换年份时自动加载对应年份的数据
- 如果该年份没有数据,显示初始化的空白模板

### 3. **数据保存**
- 编辑数据时,保存到当前选择的年份
- 如果该年份已有数据,则更新现有数据
- 如果该年份无数据,则创建新的数据记录

## 🐛 故障排查

### 问题1: 年份切换时数据不变
**可能原因**:
- 父组件没有传递正确的年份参数
- useEffect依赖项缺失

**解决方案**:
检查控制台日志:
```javascript
// 应该看到这条日志
🔄 年份切换: 2025 → 2026
📊 正在加载人力费用数据,年份: 2026
```

### 问题2: 数据库没有年份字段
**可能原因**:
- 旧数据没有year字段
- 数据保存时没有包含year字段

**解决方案**:
1. 检查数据库记录结构:
```javascript
{
  "_id": "...",
  "year": 2025,  // ✅ 必须有这个字段
  "items": [...],
  "totalBudget": 75900,
  ...
}
```

2. 如果旧数据没有year字段,可以手动更新:
```javascript
// 在CloudBase控制台执行
db.collection('hrExpenses')
  .where({ year: db.command.exists(false) })
  .update({ year: 2025 })
```

### 问题3: 所有年份看到相同数据
**可能原因**:
- 查询条件未生效
- 数据库中所有记录的year字段相同

**解决方案**:
1. 查看查询日志:
```javascript
📊 正在加载人力费用数据,年份: 2026
📊 查询结果: { data: [], ... }  // ✅ 空数组说明查询生效
```

2. 检查数据库中的year字段值

## 🎯 预期行为

### 正常流程
1. 用户选择2025年 → 加载2025年数据
2. 用户编辑并保存 → 保存到2025年
3. 用户切换到2026年 → 加载2026年数据(如无数据则显示空白)
4. 用户编辑并保存 → 保存到2026年(创建新记录)
5. 用户切换回2025年 → 加载2025年数据(数据未被覆盖)

### 数据关系
```
hrExpenses集合
├── 记录1: year=2025, items=[...], totalBudget=75900
├── 记录2: year=2026, items=[...], totalBudget=80000
├── 记录3: year=2027, items=[...], totalBudget=85000
...
```

## 📝 注意事项

1. **年份字段是必须的**: 所有记录必须包含year字段
2. **数据独立性**: 每个年份的数据完全独立,修改一个年份不影响其他年份
3. **初始数据**: 新年份首次打开时显示空白模板,需要手动输入或编辑
4. **调试日志**: 生产环境可以移除console.log,开发环境保留用于调试

## 🔧 维护建议

1. **定期检查**: 确保所有记录都有year字段
2. **数据备份**: 重要年份的数据做好备份
3. **权限控制**: 根据需要限制用户只能编辑特定年份的数据
4. **数据清理**: 过期年份的数据可以归档或删除
