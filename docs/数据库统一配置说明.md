## 数据模型统一

### Users集合结构

```typescript
{
  _id: string;                    // CloudBase自动生成
  username: string;               // 用户名（唯一）
  password: string;               // 密码（SHA-256加密）
  name: string;                   // 姓名
  email: string;                  // 邮箱
  phone: string;                  // 手机号（唯一）
  avatar: string;                 // 头像URL
  position: string;               // 职位
  departmentId: string | null;    // 部门ID
  roleIds: string[];              // 角色ID数组
  status: '在职' | '离职' | '休假'; // 员工状态
  isActive: boolean;              // 是否激活
  approvalStatus: 'pending' | 'approved' | 'rejected'; // 审核状态
  approvedBy: string | null;      // 审核人
  approvedAt: Date | null;        // 审核时间
  rejectReason: string | null;    // 拒绝原因
  needChangePassword: boolean;    // 是否需要修改密码
  lastLoginTime: Date | null;     // 最后登录时间
  createdAt: Date;                // 创建时间
  updatedAt: Date;                // 更新时间
}
```

## 登录流程

### 前端登录（直接）

```typescript
// 前端直接操作CloudBase数据库
const result = await db.collection('users')
  .where({ username })
  .get();

// 验证密码
const isValid = await verifyPassword(password, user.password);

// 生成Token
const token = generateToken(user);
```

### 后端登录（API）

```javascript
// 后端API使用相同数据库
const user = await UserCloudBase.findByUsername(username);

// 验证密码
const isValid = await UserCloudBase.comparePassword(password, user.password);

// 生成JWT Token
const token = generateToken(user);
```

## 注意事项

### 前端限制
- 前端SDK需要配置安全规则
- 敏感操作建议通过后端API

### 后端优势
- 服务端权限更高
- 可执行复杂业务逻辑
- 适合管理后台操作

### 推荐实践
1. **普通用户操作** → 前端SDK直接操作（读取、查询）
2. **敏感操作** → 通过后端API（创建用户、权限管理）
3. **复杂业务** → 后端处理（审批流程、数据统计）

## 数据库安全规则

建议在CloudBase控制台配置以下安全规则：

```javascript
// users集合读写规则示例
{
  "read": "auth.uid != null", // 登录用户可读
  "write": "auth.uid != null && (doc.userId == auth.uid || get('database.users.${auth.uid}').role == 'admin')" // 本人或管理员可写
}
```
