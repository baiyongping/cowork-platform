## 📊 权限配置详情

### 各角色默认权限

| 角色 | 查看 | 创建 | 编辑 | 删除 | 导出 |
|------|------|------|------|------|------|
| **admin（管理员）** | ✅ | ✅ | ✅ | ✅ | ✅ |
| **manager（经理）** | ✅ | ✅ | ✅ | ❌* | ✅ |
| **employee（普通员工）** | ✅ | ✅ | ❌** | ❌** | ❌ |

**注释**:
- `*` 经理：只能删除 `account` 模块（自己的账户）
- `**` 普通员工：只能编辑/删除自己创建的内容（通过数据权限控制）

### 问题管理特殊权限规则

问题管理使用 `checkIssuePermission()` 函数进行更精细的权限控制：

| 权限类型 | 说明 |
|---------|------|
| **canView** | 所有有权限的人都可以查看 |
| **canEditDetails** | 只有**发起人**可以编辑问题详情（不包括解决方式和解决结果） |
| **canEditSolution** | 只有**解决人**可以编辑解决方式和解决结果 |
| **canComment** | 所有有查询权限的人都可以添加答复与过程 |
| **canDelete** | 只有**管理员**可以删除（在组件中单独判断 admin 角色） |

## 🎯 影响范围

### 1. **菜单显示控制**
- 用户只有在拥有 `issues` 模块的 `view` 权限时才能看到"问题管理"菜单项
- 权限检查由 `Sidebar.tsx` 中的 `checkPermission('issues', 'view')` 完成

### 2. **功能操作控制**
- 创建问题：需要 `issues` 模块的 `create` 权限
- 编辑问题：需要 `issues` 模块的 `edit` 权限 + 数据权限（发起人/解决人）
- 删除问题：需要 `issues` 模块的 `delete` 权限 + admin 角色
- 导出问题：需要 `issues` 模块的 `export` 权限

### 3. **数据查询过滤**
用户只能查询以下范围的问题：
- ✅ 自己创建的问题（`owner` 字段）
- ✅ 自己是解决人的问题（`solvers` 数组）
- ✅ 下级创建的问题（如果是上级）
- ✅ 同部门的问题（如果是部门负责人）
