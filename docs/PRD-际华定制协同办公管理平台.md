## 一、产品概述

### 1.1 产品背景

际华集团是国内领先的职业装定制企业，服务于大中型国央企客户，业务特点为：
- **B2B大客户销售**：面向企业级客户，销售周期长，决策链复杂
- **定制化生产**：非标准化产品，需要个性化设计和生产
- **批量订单**：单笔订单量大，生产周期可控性要求高
- **多部门协同**：销售、设计、生产、交付等多部门需要紧密配合

现有管理方式存在痛点：
- 任务分散在各个系统和Excel中，缺乏统一管理
- 商机跟进过程不透明，转化率难以把控
- 项目执行缺乏有效监控，交付风险高
- 目标管理流于形式，战略落地困难

### 1.2 产品愿景

打造一个高效、易用、智能的协同办公管理平台，通过数字化手段提升团队协作效率，助力际华集团实现：
- 任务管理可视化、可追溯
- 商机转化率提升20%以上
- 项目交付准时率达到95%以上
- 战略目标层层分解、层层落实

### 1.3 产品定位

专为职业装定制企业设计的一体化协同办公管理平台，涵盖任务管理、商机管理、项目管理、目标管理四大核心模块。

## 三、核心功能模块

### 3.1 任务管理模块

#### 3.1.1 功能概述
支持多层级（公司级/团队级/个人级）任务创建、分配、跟踪和协同，确保任务执行透明可控。

#### 3.1.2 核心功能

**1. 任务创建**
- 支持3个任务级别：公司级、团队级、个人级
- 支持3种任务类型：
  - **日常工作**：常规性工作任务
  - **商机跟进**：关联商机的跟进任务，需选择跟进动作类型
  - **项目任务**：关联项目的执行任务，需选择项目环节
- 必填字段：
  - 任务名称
  - 任务级别
  - 任务类型
  - 任务状态（根据任务类型动态变化）
  - 负责人（默认为创建人）
  - 开始日期
  - 截止日期
  - 完成进度（0-100%）
- 可选字段：
  - 协同人（可多选）
  - 所属团队
  - 任务描述
  - 关联内容（商机/项目）
  - 任务公开性（默认公开）

**2. 商机跟进动作类型**（当任务类型为"商机跟进"时）
- 拜访客户
- 联络客户感情
- 了解年度采购计划
- 提交公司资质和案例
- 样衣展示和试穿
- 提交定制方案和报价
- 提交投标文件
- 价格谈判
- 合同条款确认
- 其它

**3. 项目任务环节**（当任务类型为"项目任务"时）
- 准备期：物料采购、样衣生产、量体数据采集
- 生产期：缝制生产、质量检验、产品入库
- 交付期：物流配送、产品交付、售后服务

**4. 任务状态管理**
- **日常工作/商机跟进**的状态（来自系统设置-任务状态设置）：
  - 未开始
  - 进行中
  - 已完成
  - 延期
  - 取消
  - 暂停
  
- **项目任务**的状态（来自系统设置-项目状态设置）：
  - 未开始
  - 准备期
  - 制造期
  - 交付期
  - 已完成
  - 暂停

**5. 任务协同**
- 支持添加多个协同人
- 协同人可以：
  - 查看任务详情
  - 添加评论
  - 接收任务通知
- 协同人不能：
  - 编辑任务
  - 删除任务
  - 修改任务状态

**6. 任务编辑**
- 编辑入口：任务详情窗口右上角"编辑任务"按钮
- 编辑权限：任务负责人或管理员
- 编辑时保留所有当前数据，支持全字段修改
- 完成进度支持滑块和数字输入双控件

**7. 任务详情查看**
- 显示任务完整信息
- 显示进度条（可视化进度百分比）
- 显示任务评论区
- 支持添加新评论

**8. 任务筛选**
- 按任务级别筛选：全部/公司级/团队级/个人级
- 按时间筛选：全部时间/本周/本月
- 关键词搜索：任务名称、负责人

**9. 任务统计**
- 总任务数
- 进行中任务数
- 已完成任务数
- 延期任务数

#### 3.1.3 业务规则

1. **任务可见性规则**
   - 公司级任务：全员可见
   - 团队级任务：团队成员可见
   - 个人级任务：
     - 公开任务：团队可见
     - 私密任务：仅负责人和协同人可见

2. **任务编辑权限规则**
   - 负责人可编辑自己负责的任务
   - 管理员可编辑所有任务
   - 协同人只能查看和评论，不能编辑

3. **任务状态变更规则**
   - 任务状态可随时手动修改
   - 当任务进度达到100%时，建议修改状态为"已完成"
   - 当任务超过截止日期且未完成时，系统标记为"延期"

4. **任务删除规则**
   - 仅管理员可删除任务
   - 删除任务会删除所有关联评论
   - 删除操作需二次确认

### 3.2 商机管理模块

#### 3.2.1 功能概述
管理B2B大客户商机全生命周期，从线索跟进到成功转化，提供四阶段管理和精准预测。

#### 3.2.2 商机四阶段

```
跟进线索 → 方案咨询 → 商务谈判 → 成功转化
```

| 阶段 | 定义 | 典型动作 | 转化条件 |
|-----|------|---------|---------|
| **跟进线索** | 获取客户信息，建立初步联系 | 拜访客户、了解需求、建立关系 | 客户有明确采购意向 |
| **方案咨询** | 提供定制方案，展示产品能力 | 样衣展示、方案设计、报价 | 客户认可方案并进入采购流程 |
| **商务谈判** | 价格谈判，合同条款确定 | 价格谈判、合同起草、法务审核 | 双方签订合同 |
| **成功转化** | 合同签订，商机转化为项目 | 创建项目、启动生产 | 合同生效，首款到账 |

#### 3.2.3 核心功能

**1. 商机创建**
- 必填字段：
  - 商机名称
  - 客户名称
  - 商机阶段（默认：跟进线索）
  - 预计金额
  - 负责人
  - 预计成交日期
- 可选字段：
  - 客户联系人
  - 联系电话
  - 商机来源
  - 商机描述
  - 竞争对手分析

**2. 商机推进**
- 支持阶段手动变更
- 阶段变更需填写备注说明
- 自动记录阶段变更历史
- 关联商机跟进任务

**3. 商机转化**
- 当商机进入"成功转化"阶段时，可一键创建关联项目
- 项目自动继承商机信息（客户名称、金额、描述等）
- 商机状态标记为"已转化"

**4. 商机数据看板**
- 各阶段商机数量统计
- 各阶段转化率分析
- 预计成交金额汇总
- 本月/本季度新增商机趋势

**5. 商机漏斗分析**
- 可视化展示商机在各阶段的分布
- 计算各阶段转化率
- 识别转化瓶颈

#### 3.2.4 业务规则

1. **商机阶段流转规则**
   - 正向流转：跟进线索 → 方案咨询 → 商务谈判 → 成功转化
   - 支持跨阶段前进（快速推进）
   - 支持后退到前一阶段（需求变化）
   - 不允许从"成功转化"后退

2. **商机负责人变更规则**
   - 部门经理可转移本部门商机
   - 管理员可转移所有商机
   - 转移时需通知原负责人和新负责人

3. **商机失败处理规则**
   - 支持标记商机为"失败"
   - 需填写失败原因
   - 失败商机不计入转化率统计

### 3.3 项目管理模块

#### 3.3.1 功能概述
管理定制生产项目全生命周期，覆盖准备期、制造期、交付期三大阶段，确保项目按时按质交付。

#### 3.3.2 项目三阶段

```
准备期 → 制造期 → 交付期
```

| 阶段 | 定义 | 关键节点 | 交付物 |
|-----|------|---------|-------|
| **准备期** | 项目启动，完成前期准备工作 | 物料采购、样衣生产、量体数据采集 | 样衣、量体数据表 |
| **制造期** | 批量生产，质量把控 | 缝制生产、质量检验、产品入库 | 成品、质检报告 |
| **交付期** | 物流配送，完成交付 | 物流配送、产品交付、售后服务 | 签收单、售后档案 |

#### 3.3.3 核心功能

**1. 项目创建**
- 来源1：从商机转化创建（自动继承商机信息）
- 来源2：手动创建新项目
- 必填字段：
  - 项目名称
  - 客户名称
  - 项目金额
  - 项目经理
  - 计划开始日期
  - 计划交付日期
  - 项目阶段（默认：准备期）
- 可选字段：
  - 项目团队成员
  - 项目描述
  - 关联商机
  - 合同编号

**2. 项目进度跟踪**
- 实时显示项目当前阶段
- 各阶段任务完成情况统计
- 项目整体进度百分比
- 项目里程碑管理

**3. 项目任务管理**
- 支持在项目下创建任务
- 任务自动关联到项目
- 任务按项目环节分类显示
- 任务完成度影响项目进度

**4. 项目风险预警**
- 任务延期预警
- 关键节点逾期预警
- 预算超支预警
- 质量问题预警

**5. 项目数据看板**
- 项目总数统计
- 各阶段项目数量
- 按时交付率
- 项目盈利分析

#### 3.3.4 业务规则

1. **项目阶段流转规则**
   - 顺序流转：准备期 → 制造期 → 交付期
   - 不支持跨阶段前进
   - 不支持阶段回退（特殊情况需管理员审批）
   - 每个阶段完成需要确认关键交付物

2. **项目任务关联规则**
   - 项目任务必须关联到项目环节
   - 项目环节必须属于当前项目阶段
   - 例：项目在"准备期"时，只能创建"物料采购/样衣生产/量体数据采集"任务

3. **项目完成条件**
   - 所有任务状态为"已完成"
   - 项目阶段为"交付期"
   - 客户验收通过
   - 尾款收齐

### 3.4 目标管理模块

#### 3.4.1 功能概述
支持从年度战略到季度措施的目标层层分解，实现战略落地和过程监控。

#### 3.4.2 目标分解体系

```
年度战略目标 → 季度执行目标 → 月度行动措施
```

| 层级 | 定义 | 制定者 | 周期 | 示例 |
|-----|------|-------|------|------|
| **年度战略目标** | 公司年度战略方向和核心指标 | 高层领导 | 1年 | 销售额增长30% |
| **季度执行目标** | 战略目标的季度分解 | 部门经理 | 1季度 | Q1销售额达到5000万 |
| **月度行动措施** | 具体可执行的行动计划 | 部门经理/项目经理 | 1月 | 开发10个新客户 |

#### 3.4.3 核心功能

**1. 目标创建**
- 支持3个目标层级：年度/季度/月度
- 支持目标类型：
  - 业绩类：销售额、利润、市场份额
  - 客户类：新客户数、客户满意度、复购率
  - 项目类：项目数量、交付准时率、质量合格率
  - 管理类：流程优化、人员培训、系统建设
- 必填字段：
  - 目标名称
  - 目标层级
  - 目标类型
  - 目标值（数值）
  - 目标单位
  - 负责人
  - 开始日期
  - 结束日期
- 可选字段：
  - 父级目标（用于分解）
  - 目标描述
  - 衡量标准

**2. 目标分解**
- 支持将年度目标分解为季度目标
- 支持将季度目标分解为月度目标
- 子目标自动关联父目标
- 子目标完成度自动汇总到父目标

**3. 目标进度跟踪**
- 实时显示目标完成百分比
- 完成值 vs 目标值对比
- 进度趋势图
- 预测完成时间

**4. 目标对齐检查**
- 检查部门目标是否对齐公司目标
- 检查个人目标是否对齐部门目标
- 识别目标冲突和重复

**5. 目标数据看板**
- 目标完成率排行
- 目标达成分析
- 关键目标预警
- 目标复盘报告

#### 3.4.4 业务规则

1. **目标分解规则**
   - 子目标之和应接近父目标值（允许±10%误差）
   - 子目标时间范围必须在父目标范围内
   - 子目标负责人可以不同于父目标负责人

2. **目标调整规则**
   - 月度目标可随时调整
   - 季度目标调整需部门经理审批
   - 年度目标调整需高层领导审批
   - 调整需记录原因和审批人

3. **目标考核规则**
   - 月度目标完成率影响月度绩效
   - 季度目标完成率影响季度绩效
   - 年度目标完成率影响年终奖金

### 3.5 系统设置模块

#### 3.5.1 功能概述
提供系统基础配置，包括用户管理、角色权限、类型设置、操作日志等。

#### 3.5.2 核心功能

**1. 用户管理**
- 用户添加/编辑/删除
- 用户角色分配
- 用户状态管理（启用/禁用）
- 密码重置

**2. 角色权限管理**
- 角色创建/编辑/删除
- 权限点配置
- 角色成员管理

**3. 类型设置**

**3.3.1 任务类型设置**
- 预置类型：日常工作、商机跟进、项目任务
- 支持新增自定义类型
- 支持编辑和删除（有关联数据时不可删除）

**3.3.2 任务状态设置**
- 预置状态：未开始、进行中、已完成、延期、取消、暂停
- 适用于"日常工作"和"商机跟进"类型任务
- 支持新增和删除状态
- 删除时检查是否有任务使用该状态

**3.3.3 项目状态设置**
- 预置状态：未开始、准备期、制造期、交付期、已完成、暂停
- 适用于"项目任务"类型任务
- 项目状态与项目阶段对应
- 支持新增和删除状态

**3.3.4 商机阶段设置**
- 预置阶段：跟进线索、方案咨询、商务谈判、成功转化
- 支持新增自定义阶段
- 支持调整阶段顺序

**3.3.5 项目阶段设置**
- 预置阶段：准备期、制造期、交付期
- 支持新增自定义阶段
- 每个阶段可配置关键节点

**4. 操作日志**
- 记录所有重要操作
- 日志字段：操作人、操作模块、操作类型、操作内容、操作时间、IP地址

## 五、技术规格说明

### 5.1 技术栈

**前端框架**
- React 18+
- TypeScript
- Tailwind CSS 4.0

**UI组件库**
- Lucide React（图标库）
- 自定义组件库

**状态管理**
- React Hooks (useState, useEffect等)

**推荐后端技术栈**（供开发团队参考）
- Node.js + Express / NestJS
- 或 Python + Django / FastAPI
- 或 Java + Spring Boot

**推荐数据库**
- PostgreSQL（主数据库）
- Redis（缓存）

### 5.2 代码规范

**命名规范**
- 组件文件：PascalCase（如 `TaskManagement.tsx`）
- 工具函数：camelCase（如 `getStatusColor.ts`）
- 常量：UPPER_SNAKE_CASE（如 `MAX_FILE_SIZE`）
- CSS类名：kebab-case（如 `task-card`）

**TypeScript规范**
- 所有组件必须定义Props接口
- 所有函数必须定义参数和返回值类型
- 优先使用类型推断，复杂类型显式声明

**组件结构规范**
```
/components
  /pages          # 页面级组件
  /common         # 通用组件
  /layouts        # 布局组件
/styles           # 全局样式
/utils            # 工具函数
/types            # 类型定义
/hooks            # 自定义Hooks
```

### 5.3 性能要求

- 首屏加载时间 < 2秒
- 页面切换响应时间 < 300ms
- 表格数据渲染（1000条）< 500ms
- 支持并发用户数：100+

### 5.4 浏览器兼容性

- Chrome 90+
- Edge 90+
- Firefox 88+
- Safari 14+

### 5.5 响应式设计

- 桌面端：>= 1280px（主要适配）
- 平板端：768px - 1279px（部分适配）
- 移动端：< 768px（暂不支持）
