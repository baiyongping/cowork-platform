# 用户审核管理 - 原型设计文档

## 📋 功能概述

在系统设置中增加"用户审核"Tab，管理员可以查看所有注册用户的审核状态，对待审核用户进行通过/拒绝操作，并自动发送短信通知。

## 📊 数据展示设计

### 2.1 用户信息列（左侧）

**设计要点**:
- **头像**: 圆形头像，使用首字母+渐变背景色
- **姓名**: 粗体显示，突出主要信息
- **用户名**: @username 格式，灰色次要信息
- **特殊标识**: admin用户显示紫色"管理员"徽章

**示例**:
```
┌──────────────────────┐
│  👤  张三             │
│     @zhangsan        │
│     [管理员]          │  ← 仅admin显示
└──────────────────────┘
```

### 2.2 角色/部门列

**显示内容**:
- 第一行: 角色名称（如：销售经理、管理员）
- 第二行: 部门名称（如：销售部）

**示例**:
```
销售经理
销售部
```

### 2.3 联系方式列

**显示内容**:
- 📱 手机号（脱敏显示: 138****8000）
- 📧 邮箱（如果有）

**示例**:
```
📱 138****8000
📧 zhang@company.com
```

### 2.4 注册时间列

**显示内容**:
- 主要时间: YYYY-MM-DD 格式
- 次要信息: 上次登录时间（灰色小字）

**示例**:
```
2025-12-01
上次登录: 2025-12-05
```

### 2.5 审核状态列

**状态设计**:

1. **⏱️ 待审核** (Pending)
   - 颜色: 黄色 `bg-yellow-50 text-yellow-700`
   - 图标: Clock (⏱️)
   - 说明: 新注册用户，等待管理员审核

2. **✅ 已通过** (Approved)
   - 颜色: 绿色 `bg-green-50 text-green-700`
   - 图标: CheckCircle (✅)
   - 显示审核时间（小字）

3. **❌ 已拒绝** (Rejected)
   - 颜色: 红色 `bg-red-50 text-red-700`
   - 图标: XCircle (❌)
   - 显示拒绝原因（小字）

### 2.6 操作列

**根据审核状态显示不同操作**:

| 状态 | 操作按钮 | 说明 |
|------|---------|------|
| 待审核 | `[✅ 通过]` `[❌ 拒绝]` | 绿色+红色按钮 |
| 已通过 | 灰色文字"已审核" | admin用户不显示操作 |
| 已拒绝 | `[🔄 重新审核]` | 蓝色按钮 |

## 📱 审核操作流程

### 4.1 审核通过流程

```
用户点击 [✅ 通过] 按钮
    ↓
弹出确认对话框
┌─────────────────────────────────────┐
│  ⚠️ 确认审核通过                     │
│                                     │
│  确认通过用户 张三 (@zhangsan) 的    │
│  注册申请吗？                        │
│                                     │
│  📱 审核通过后将发送短信通知用户     │
│                                     │
│     [取消]         [确认通过] ✅     │
└─────────────────────────────────────┘
    ↓
发送API请求
    ↓
更新数据库状态为 'approved'
    ↓
调用短信服务发送通知
    ↓
显示成功提示
┌─────────────────────────────────────┐
│  ✅ 审核通过成功！                   │
│                                     │
│  已向用户 138****8000 发送短信通知   │
└─────────────────────────────────────┘
    ↓
刷新用户列表
```

### 4.2 审核拒绝流程

```
用户点击 [❌ 拒绝] 按钮
    ↓
弹出拒绝原因输入框
┌─────────────────────────────────────┐
│  ❌ 拒绝注册申请                     │
│                                     │
│  用户: 张三 (@zhangsan)              │
│                                     │
│  请填写拒绝原因: *                   │
│  ┌───────────────────────────────┐ │
│  │ 例如: 信息不完整、部门不匹配等 │ │
│  │                               │ │
│  │                               │ │
│  └───────────────────────────────┘ │
│                                     │
│  📱 拒绝后将发送短信通知用户         │
│                                     │
│     [取消]         [确认拒绝] ❌     │
└─────────────────────────────────────┘
    ↓
验证拒绝原因是否填写
    ↓
发送API请求
    ↓
更新数据库状态为 'rejected'
记录拒绝原因
    ↓
调用短信服务发送通知（包含原因）
    ↓
显示成功提示
┌─────────────────────────────────────┐
│  ✅ 已拒绝注册申请                   │
│                                     │
│  已向用户 138****8000 发送短信通知   │
└─────────────────────────────────────┘
    ↓
刷新用户列表
```

### 4.3 重新审核流程

```
用户点击 [🔄 重新审核] 按钮
    ↓
直接执行"审核通过"流程
（已拒绝的用户重新审核后状态变为'approved'）
```

| 字段名 | 类型 | 说明 | 示例 |
|-------|------|------|------|

| `name` | string | 姓名 | `"张三"` |

### 9.2 数据加载

```typescript
// 从CloudBase数据库加载用户数据
const loadUsers = async () => {
  try {
    const res = await db.collection('users')
      .orderBy('createdAt', 'desc')
      .get();
    
    setUsers(res.data);
    
    // 计算待审核数量
    const pending = res.data.filter(u => u.approvalStatus === 'pending');
    setPendingCount(pending.length);
  } catch (error) {
    console.error('加载用户失败:', error);
  }
};
```

### 9.3 审核操作

```typescript
// 审核通过
const handleApprove = async (user) => {
  if (!confirm(`确认通过 ${user.name} 的注册申请吗？\n\n审核通过后将发送短信通知用户。`)) {
    return;
  }
  
  try {
    // 更新数据库
    await db.collection('users').doc(user._id).update({
      approvalStatus: 'approved',
      approvedBy: currentUser.userId,
      approvedAt: new Date(),
    });
    
    // 发送短信通知
    if (user.phone) {
      await sendApprovalSuccessSms(user.phone, user.name);
    }
    
    alert('审核通过成功！');
    loadUsers(); // 刷新列表
  } catch (error) {
    console.error('审核失败:', error);
    alert('审核失败，请重试');
  }
};
```
