# 问题管理权限并集实现说明

## 📋 背景

在问题管理模块中，当**发起人和解决人是同一人**时，用户应该同时拥有两种角色的权限，即采用**权限并集**的方式。

## 🔧 实现原理

### 权限定义

在 `utils/permission.ts` 的 `checkIssuePermission` 函数中：

```typescript
/**
 * 检查问题管理的权限（专用）
 * 
 * 权限规则说明：
 * 1. 当发起人和解决人是同一人时，权限采用并集方式
 * 2. isOwner = true 时，拥有编辑问题详情的权限
 * 3. isSolver = true 时，拥有编辑解决方式和解决结果的权限
 * 4. 当两个角色重合时，同时拥有两种权限
 */
export function checkIssuePermission(currentUserId: string, issue: any) {
  const isOwner = currentUserId === issue.owner?._id || currentUserId === issue.owner;
  const isSolver = issue.solvers?.some((s: any) => 
    (typeof s === 'string' ? s : s._id) === currentUserId
  );
  
  // ✅ 权限并集：当发起人和解决人是同一人时，拥有两种权限
  const canEditDetails = isOwner; // 发起人可以编辑问题详情
  const canEditSolution = isSolver; // 解决人可以编辑解决方式和解决结果
  
  return {
    canView: true,
    
    // ✅ 发起人可以编辑，即使同时是解决人也拥有此权限
    canEditDetails,
    
    // ✅ 解决人可以编辑，即使同时是发起人也拥有此权限
    canEditSolution,
    
    canComment: true,
    canDelete: false,
    
    // 角色标识
    isOwner,
    isSolver
  };
}
```

### 关键点

1. **独立判断**：`canEditDetails` 和 `canEditSolution` 是独立判断的
2. **并集效果**：当 `isOwner = true` 且 `isSolver = true` 时：
   - `canEditDetails = true`
   - `canEditSolution = true`
   - 用户同时拥有两种权限

## 📊 权限矩阵

| 角色组合 | isOwner | isSolver | canEditDetails | canEditSolution | 说明 |
|---------|---------|----------|----------------|-----------------|------|
| 仅发起人 | ✅ | ❌ | ✅ | ❌ | 只能编辑问题详情 |
| 仅解决人 | ❌ | ✅ | ❌ | ✅ | 只能编辑解决方式和解决结果 |
| **发起人 + 解决人** | **✅** | **✅** | **✅** | **✅** | **同时拥有两种权限（并集）** |
| 其他人 | ❌ | ❌ | ❌ | ❌ | 只能查看和评论 |

## 🎯 实际应用场景

### 场景1：自己给自己分配问题

**情况**：
- 发起人：张三（userId: "user-001"）
- 解决人：张三（userId: "user-001"）

**权限结果**：
```typescript
{
  canView: true,
  canEditDetails: true,     // ✅ 因为是发起人
  canEditSolution: true,    // ✅ 因为是解决人
  canComment: true,
  canDelete: false,         // ❌ 只有管理员
  isOwner: true,
  isSolver: true
}
```

**可以执行的操作**：
- ✅ 编辑问题标题
- ✅ 编辑问题类型
- ✅ 编辑问题状态
- ✅ 编辑重要程度
- ✅ 编辑紧急程度
- ✅ 编辑开始/结束日期
- ✅ 编辑发起人
- ✅ 编辑解决人
- ✅ 编辑问题描述
- ✅ 编辑解决方式
- ✅ 编辑解决结果
- ✅ 添加回复
- ❌ 删除问题（只有管理员）

### 场景2：分配给其他人

**情况**：
- 发起人：张三（userId: "user-001"）
- 解决人：李四（userId: "user-002"）

**张三的权限**：
```typescript
{
  canView: true,
  canEditDetails: true,     // ✅ 因为是发起人
  canEditSolution: false,   // ❌ 不是解决人
  canComment: true,
  canDelete: false,
  isOwner: true,
  isSolver: false
}
```

**李四的权限**：
```typescript
{
  canView: true,
  canEditDetails: false,    // ❌ 不是发起人
  canEditSolution: true,    // ✅ 因为是解决人
  canComment: true,
  canDelete: false,
  isOwner: false,
  isSolver: true
}
```

## 💡 UI层面的体现

在 `EditIssueModal.tsx` 中，权限控制体现在：

```typescript
// 获取权限
const permission = currentUser 
  ? checkIssuePermission(currentUser._id, issue)
  : { canEditDetails: false, canEditSolution: false };

// 应用权限到表单字段
<input
  disabled={!permission.canEditDetails}
  // ... 问题详情字段
/>

<textarea
  disabled={!permission.canEditSolution}
  // ... 解决方式和解决结果字段
/>
```

### 当发起人 = 解决人时的UI效果

- ✅ 所有表单字段都是**可编辑**状态
- ✅ 没有任何字段被禁用（`disabled={false}`）
- ✅ 用户体验流畅，无需切换角色

1. **权限并集实现**：通过独立判断 `isOwner` 和 `isSolver`，自然实现了权限并集
2. **代码简洁**：无需额外的逻辑处理"同一人"的特殊情况
3. **易于理解**：权限规则清晰，便于维护
