1️⃣ users - 用户信息表 (已优化)

字段结构

字段名 类型 必填 说明
_idstring是MongoDB主键
_openidstring否CloudBase用户标识
usernamestring是用户名（唯一）
passwordstring是密码（SHA-256）
emailstring是邮箱（唯一）
phonestring是手机号
namestring是真实姓名
nicknamestring否昵称 🆕
signaturestring否个性签名 🆕
roleenum是角色: admin | user
departmentstring是部门
avatarstring否头像URL
wechatOpenIdstring否微信OpenID（微信公众号/小程序用户唯一标识）🆕
wechatUnionIdstring否微信UnionID（同一主体下多应用用户唯一标识）🆕
isActiveboolean是是否激活

  • username (唯一索引)
  • email (唯一索引)
  • _openid (普通索引)
  • wechatOpenId (普通索引) 🆕
  • wechatUnionId (普通索引) 🆕
✅ 微信对接说明:
  • wechatOpenId: 用于微信公众号/小程序内的用户身份识别
  • wechatUnionId: 用于同一主体下多个应用间的用户身份统一（需微信开放平台）
  • 登录流程: 微信授权 → 获取OpenID/UnionID → 绑定或创建用户

9️⃣ product_items - 产品明细表 (🆕 新增)

字段结构

字段名 类型 必填 说明
_idstring是MongoDB主键
categorystring是产品类别（如：服装、装备、鞋靴等）
namestring是产品名称
specificationstring否规格型号
quantitynumber是数量
unitstring是单位（如：件、套、双等）

索引

  • category (普通索引)
  • createdAt (降序索引)
✅ 产品明细表说明:
  • 统一管理: 商机需求和项目交付产品使用同一个表
  • 字段说明:
    • category: 产品类别，如服装、装备、鞋靴等
    • quantity: 产品数量
    • salesPrice: 销售单价（对客户报价）
    • costPrice: 成本单价（内部成本核算）
    • totalAmount: 总价 = 数量 × 销售单价
  • 关联关系:
    • 商机通过 opportunities.productItemIds[] 关联
    • 项目通过 projects.productItemIds[] 关联

🚀 v2.0 优化总结

✅ 主要改进

  1. 微信对接支持
    • 用户表新增 wechatOpenId、wechatUnionId 字段
    • 支持微信公众号/小程序用户身份识别
    • 支持同一主体下多应用用户统一
  2. 用户体验优化
    • 用户表新增 nickname（昵称）字段
    • 用户表新增 signature（个性签名）字段
  3. 任务关联增强
    • 明确关联字段：relatedOpportunityId、relatedProjectId、relatedTaskId、relatedQuarterlyMeasureId
    • 废弃模糊的 relatedTo 字段
    • 支持父子任务关系
    • 支持季度措施关联
  4. 产品明细独立管理
    • 新增 product_items 表
    • 统一管理商机需求和项目交付产品
    • 包含产品类别、数量、销售单价、成本单价、总价
    • 支持多对多关联（一个商机/项目可关联多个产品）

⚠️ 数据迁移注意事项

  • 用户表: 新增字段为可选，不影响现有数据
  • 任务表: 需要将 relatedTo 数据迁移到对应的明确字段
  • 商机表: 需要将 productType 数据转换为 product_items 记录
  • 项目表: 需要创建对应的 product_items 记录
