# 问题管理功能测试指南

## 📋 测试概述

本指南用于验证问题管理模块的完整功能,包括问题类型配置、CRUD操作、附件管理等。

## ✅ 已完成的功能

### 1. 数据库配置 ✓

**问题类型配置** (`type_settings` 集合)
```json
{
  "type": "issueType",
  "values": [
    { "value": "技术问题", "enabled": true },
    { "value": "流程问题", "enabled": true },
    { "value": "资源问题", "enabled": true },
    { "value": "沟通问题", "enabled": true },
    { "value": "其他", "enabled": true }
  ]
}
```

**验证方法**:
```bash
node database/verify-issue-types.js
```

### 2. 前端组件 ✓

#### 主要组件
- ✅ `IssueManagementPage.tsx` - 问题管理主页面
- ✅ `CreateIssueModal.tsx` - 创建问题弹窗
- ✅ `EditIssueModal.tsx` - 编辑问题弹窗
- ✅ `IssueDetailModal.tsx` - 问题详情弹窗
- ✅ `IssueCard.tsx` - 问题卡片组件
- ✅ `IssueRecycleBin.tsx` - 回收站组件
- ✅ `AttachmentUploader.tsx` - 附件上传组件
- ✅ `AttachmentViewer.tsx` - 附件查看组件

#### 功能特性
- ✅ 问题类型动态加载(从 `type_settings` 读取)
- ✅ 问题状态管理(待接受、进行中、已完成、已关闭)
- ✅ 解决结果记录(未解决、已解决、转需求)
- ✅ 优先级和紧急程度设置
- ✅ 附件上传和管理
- ✅ 协同人员选择
- ✅ 回收站功能
- ✅ 权限控制(基于角色和所有者)

### 3. 类型定义 ✓

**文件**: `types/issue.ts`

```typescript
export type IssueType = '技术问题' | '流程问题' | '资源问题' | '沟通问题' | '其他';
export type IssueStatus = '待接受' | '进行中' | '已完成' | '已关闭';
export type IssueResult = '未解决' | '已解决' | '转需求';
export type IssuePriority = '极重要' | '很重要' | '一般重要';
export type IssueUrgency = '立即解决' | '尽快解决' | '近期解决';
```

### 步骤 2: 启动开发服务器

```bash
npm run dev
```

访问: `http://localhost:5173`

### 步骤 3: 测试创建问题

1. 点击"创建问题"按钮
2. 验证问题类型下拉框显示5个选项:
   - 技术问题
   - 流程问题
   - 资源问题
   - 沟通问题
   - 其他
3. 填写必填字段:
   - 问题名称
   - 问题类型
   - 问题级别
   - 重要程度
   - 紧急程度
   - 开始日期
   - 结束日期
4. 可选操作:
   - 添加问题描述及建议
   - 上传附件
   - 选择协同人员
5. 点击"创建"按钮

**预期结果**:
- ✅ 问题创建成功
- ✅ 返回问题列表页面
- ✅ 新问题出现在列表中
- ✅ 问题卡片显示完整信息

### 步骤 4: 测试编辑问题

2. 修改问题信息:

   - 更新问题描述
   - 添加/删除附件
3. 点击"保存"按钮

**预期结果**:
- ✅ 问题更新成功
- ✅ 返回问题列表页面
- ✅ 问题卡片显示更新后的信息

### 步骤 5: 测试查看详情

1. 点击问题卡片
2. 查看问题详情弹窗

**预期内容**:
- ✅ 基本信息(名称、类型、状态等)

- ✅ 附件列表(支持预览和下载)

- ✅ 创建和修改信息

### 步骤 6: 测试删除和回收站
