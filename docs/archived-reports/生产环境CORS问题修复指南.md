# 生产环境 CORS 问题修复指南

## 问题描述

生产环境访问时出现 CORS 错误：

```
POST https://cowork-9gg9oocb516be5fb.ap-shanghai.tcb-api.tencentcloudapi.com/auth/v1/signin/anonymously
→ 403 Forbidden

错误信息: 'cors permission denied, please check if 152.136.183.81 in your client cowork-9gg9oocb516be5fb domains'
```

## 根本原因

CloudBase 生产环境（`cowork-9gg9oocb516be5fb`）的**安全域名配置**中缺少服务器 IP 地址 `152.136.183.81`

## 修复方案

### 方案一：配置安全域名（推荐）

1. **访问 CloudBase 控制台**：
   https://tcb.cloud.tencent.com/dev?envId=cowork-9gg9oocb516be5fb#/settings

2. **找到「安全域名配置」**

3. **添加以下域名**：
   - `http://152.136.183.81`
   - `https://152.136.183.81`
   - `http://jihuadz.xin`
   - `https://jihuadz.xin`

## 工作原理

### 1. 匿名登录的作用
CloudBase SDK 要求所有数据库操作都必须有认证上下文。匿名登录提供了一个临时的认证状态。

### 2. 为什么可以跳过匿名登录？
- 我们使用**自定义用户系统**（而非 CloudBase 内置用户系统）
- 用户登录后，我们**手动调用云函数**进行认证
- 云函数内部使用 `wxContext.OPENID` 或自定义逻辑验证用户
- 因此匿名登录失败不影响系统核心功能

### 3. 安全性说明
- ✅ 用户必须通过登录页输入用户名密码
- ✅ 后端云函数验证用户身份
- ✅ 权限控制在后端实现
- ⚠️ 匿名登录失败后，未登录用户无法访问任何数据

## 长期解决方案

**强烈建议配置安全域名（方案一）**，理由：

1. **完整性**：系统初始化更流畅
2. **稳定性**：避免依赖代码容错机制
3. **规范性**：符合 CloudBase 最佳实践
4. **未来扩展**：如果后续需要使用 CloudBase 实时数据库、存储等功能，必须有匿名登录
