## 📝 需求变更内容

### 1. admin超级管理员特殊规则
**原需求**: admin在数据库中定义权限配置  
**新需求**: 
- admin超级管理员**无需在数据库中定义权限**
- 代码层面直接给予**所有功能的完整权限**
- 检查到 `roleId === 'admin'` 时，直接返回true，跳过权限查询

**影响范围**:
- `database/seeds/001_init_roles.sql`: 删除admin角色INSERT语句
- `server/utils/permissionChecker.ts`: checkFunctionPermission函数增加admin判断

---

### 2. 系统设置模块权限扩展

**新增功能模块**: `settings` (系统设置)

| 子功能 | 功能名称 | 权限操作 |
|-------|---------|---------|
| `userApproval` | 用户审核 | view, create, edit, delete, export |
| `employees` | 员工管理 | view, create, edit, delete, export |
| `departments` | 部门管理 | view, create, edit, delete, export |
| `roles` | 角色权限 | view, create, edit, delete, export |
| `typeSettings` | 类型设置 | view, create, edit, delete, export |
| `operationLogs` | 操作日志 | view, create, edit, delete, export |

**影响范围**:
- `database/seeds/001_init_roles.sql`: 3个角色(employee, manager, executive)添加settings模块权限

### 2. `server/utils/permissionChecker.ts` 更新

#### `checkFunctionPermission` 函数修改

**新增admin判断逻辑**:
```typescript
export function checkFunctionPermission(
  user: User | null,              // 新增user参数
  rolePermissions: RolePermission | null,
  module: string,
  action: 'view' | 'create' | 'edit' | 'delete' | 'export',
  subModule?: string
): boolean {
  // admin超级管理员拥有所有功能权限
  if (user && user.roleId === 'admin') {
    return true;  // 直接返回true,跳过权限检查
  }

  // 原有逻辑...
}
```

**关键修改点**:
1. 函数签名新增 `user: User | null` 参数
2. 在函数开头增加admin判断: `if (user && user.roleId === 'admin') return true;`
3. 注释更新: "子模块名称(可选,用于目标管理、**系统设置**等)"

#### 连锁更新

**`canEdit` 函数**:

## 🎯 权限设计原则总结

### admin角色处理
1. **数据库**: 不存储admin角色权限配置
2. **代码层**: 检测到 `roleId === 'admin'` 直接返回全部权限
3. **优势**: 简化权限管理，admin始终拥有最高权限，无需配置维护

### 系统设置模块权限分级

| 功能 | 普通员工 | 部门经理 | 高管 | admin |
|-----|---------|---------|-----|-------|
| 用户审核 | ❌ | ✅ 审核 | ✅ 审核 | ✅ 全部 |
| 员工管理 | ❌ | ✅ 部分管理 | ✅ 全部管理 | ✅ 全部 |
| 部门管理 | ❌ | ❌ 查看 | ✅ 全部管理 | ✅ 全部 |
| 角色权限 | ❌ | ❌ 查看 | ❌ 查看 | ✅ 全部 |
| 类型设置 | ❌ | ❌ 查看 | ✅ 全部管理 | ✅ 全部 |
| 操作日志 | ❌ | ✅ 查看导出 | ✅ 查看导出 | ✅ 全部 |
