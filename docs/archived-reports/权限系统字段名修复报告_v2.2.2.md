# 权限系统字段名修复报告 v2.2.2

## 修复日期
2025-12-16

## 问题描述

**现象:**
- 用户 b02 创建任务后，在任务列表中看不到自己创建的任务
- 管理员 admin 可以看到该任务
- 同样的问题在商机管理和项目管理模块也存在

**影响范围:**
- ✅ 任务管理模块
- ✅ 商机管理模块
- ✅ 项目管理模块

## 问题根源分析

### 字段名不一致问题

**权限查询逻辑** (`utils/permission.ts` - `buildQueryConditions` 函数):
```typescript
const conditions: any[] = [
  { ownerId: currentUserId },        // ❌ 使用 ownerId
  { collaborators: currentUserId }
];

if (subordinates.length > 0) {
  conditions.push({ ownerId: { $in: subordinates } }); // ❌ 使用 ownerId
}
```

**实际数据结构** (所有创建模态框):

| 模块 | 文件 | 字段名 | 行号 |
|------|------|--------|------|
| 任务 | `CreateTaskModal.tsx` | `owner` | 52, 107 |
| 商机 | `CreateOpportunityModal.tsx` | `owner` | 18, 95, 142 |
| 项目 | `CreateProjectModal.tsx` | `owner` | 22, 48, 180 |

**冲突:**
- 权限查询使用字段: `ownerId`
- 实际数据存储字段: `owner`
- 导致查询条件永远无法匹配 → 普通用户看不到自己创建的数据

### 为什么管理员能看到?

```typescript:259-261:utils/permission.ts
// 管理员可以查看所有数据
if (currentUserRole === 'admin') {
  return {}; // 返回空查询条件 = 不过滤 = 查询所有
}
```

管理员绕过了字段名检查,所以不受影响。

## 修复方案

### 修复内容

**文件:** `utils/permission.ts`
**函数:** `buildQueryConditions`
**修复:** 将所有 `ownerId` 统一改为 `owner`

**修复前:**
```typescript
const conditions: any[] = [
  { ownerId: currentUserId },
  { collaborators: currentUserId }
];

if (subordinates.length > 0) {
  conditions.push({ ownerId: { $in: subordinates } });
}

if (departments.length > 0) {
  // ...
  conditions.push({
    ownerId: { $in: deptUserIds },
    isPublic: true
  });
}
```

**修复后:**
```typescript
const conditions: any[] = [
  { owner: currentUserId },          // ✅ 改为 owner
  { collaborators: currentUserId }
];

if (subordinates.length > 0) {
  conditions.push({ owner: { $in: subordinates } }); // ✅ 改为 owner
}

if (departments.length > 0) {
  // ...
  conditions.push({
    owner: { $in: deptUserIds },     // ✅ 改为 owner
    isPublic: true
  });
}
```
