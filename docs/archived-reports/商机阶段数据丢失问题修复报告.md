# 商机阶段数据丢失问题修复报告

## 问题描述

每次重启系统后,商机阶段设置的数据项会只剩下最初的三项(**跟进线索、方案咨询、商务谈判**),其它新增项都会丢失。

## 问题根因分析

### 1. 主要问题:缺少数据库初始化逻辑

**文件**: `components/pages/SystemSettings.tsx`

在`loadTypeSettings`函数中,存在以下问题:

```typescript
// 旧代码(第114-164行)
const loadTypeSettings = async () => {
  try {
    const result = await db.collection('type_settings').get();
    
    const defaults: Record<string, string[]> = {
      // ... 默认值配置
      opportunity: ['跟进线索', '方案咨询', '商务谈判'],
      // ...
    };
    
    const typeMap: Record<string, string[]> = {};
    if (result.data && Array.isArray(result.data)) {
      result.data.forEach((item: any) => {
        typeMap[item.type] = item.values || defaults[item.type] || [];
      });
    }
    
    // ⚠️ 问题: 如果数据库中没有记录,直接使用默认值,但不保存到数据库
    setOpportunityStages(typeMap.opportunity || defaults.opportunity);
  } catch (error) {
    // ⚠️ 错误处理也使用硬编码默认值
    setOpportunityStages(['跟进线索', '方案咨询', '商务谈判']);
  }
};
```

**问题说明:**
- 首次加载时,如果`type_settings`集合为空,系统使用默认值但**不保存到数据库**
- 用户在系统设置中新增商机阶段后,数据确实保存到了数据库
- 但当重启系统或刷新页面后,`loadTypeSettings`重新执行
- 如果由于某种原因(网络延迟、数据库连接问题等)读取数据失败或返回空数据,会再次使用硬编码默认值
- 导致之前新增的数据"丢失"(实际是被默认值覆盖)

### 2. 次要问题:多处硬编码默认值

以下组件都包含硬编码的商机阶段默认值:
- `components/OpportunitySelector.tsx`
- `components/pages/OpportunityManagement.tsx`
- `components/OpportunityDetailModal.tsx`
- `components/EditOpportunityModal.tsx`
- `components/CreateOpportunityModal.tsx`
- `components/OpportunityRecycleBin.tsx`
- `components/OpportunityRecycleBinDetail.tsx`

这些组件在加载失败时都会回退到默认的三个阶段,虽然不是主要问题,但增加了数据不一致的风险。

## 修复方案

### 核心修复:数据库初始化逻辑

**修改文件**: `components/pages/SystemSettings.tsx` (第114-183行)

```typescript
const loadTypeSettings = async () => {
  try {
    const result = await db.collection('type_settings').get();
    
    const defaults: Record<string, string[]> = {
      task: ['日常工作', '商机跟进', '项目任务'],
      taskStatus: ['未开始', '进行中', '已完成', '延期', '取消', '暂停'],
      opportunity: ['跟进线索', '方案咨询', '商务谈判'],
      action: ['拜访客户', '联络客户感情', '了解年度采购计划', '提交公司资质和案例', '样衣展示和试穿', '提交定制方案和报价', '提交投标文件', '价格谈判', '合同条款确认', '其它'],
      preparation: ['物料采购', '样衣生产', '量体数据采集'],
      production: ['缝制生产', '质量检验', '产品入库'],
      delivery: ['物流配送', '产品交付', '售后服务'],
      projectStatus: ['未开始', '准备期', '制造期', '交付期', '已完成', '暂停'],
      productType: ['西服套装', '衬衫', '大衣', '冲锋衣', '休闲裤', '配饰', '其它']
    };
    
    // ✅ 新增: 跟踪已存在的类型
    const typeMap: Record<string, string[]> = {};
    const existingTypes = new Set<string>();
    
    if (result.data && Array.isArray(result.data)) {
      result.data.forEach((item: any) => {
        typeMap[item.type] = item.values || [];
        existingTypes.add(item.type);
      });
    }
    
    // ✅ 新增: 检查并初始化缺失的类型设置
    for (const [type, defaultValues] of Object.entries(defaults)) {
      if (!existingTypes.has(type)) {
        // 数据库中没有该类型设置,创建并保存默认值
        console.log(`初始化类型设置: ${type}`);
        await db.collection('type_settings').add({
          type,
          values: defaultValues,
          createdAt: new Date(),
          updatedAt: new Date()
        });
        typeMap[type] = defaultValues;
      } else if (!typeMap[type] || typeMap[type].length === 0) {
        // 数据库中有记录但values为空,使用默认值
        typeMap[type] = defaultValues;
      }
    }
    
    // 设置各类型数据
    setTaskTypes(typeMap.task || defaults.task);
    setTaskStatuses(typeMap.taskStatus || defaults.taskStatus);
    setOpportunityStages(typeMap.opportunity || defaults.opportunity);
    setOpportunityActionTypes(typeMap.action || defaults.action);
    setPreparationPhases(typeMap.preparation || defaults.preparation);
    setProductionPhases(typeMap.production || defaults.production);
    setDeliveryPhases(typeMap.delivery || defaults.delivery);
    setProjectStatuses(typeMap.projectStatus || defaults.projectStatus);
    setProductTypes(typeMap.productType || defaults.productType);
    
    console.log('类型设置加载完成:', typeMap);
    
  } catch (error) {
    console.error('加载类型设置失败:', error);
    // 出错时使用默认值,但不保存到数据库
    // ... (保留原有错误处理)
  }
};
```

### 修复要点

1. **新增existingTypes追踪**: 使用`Set`记录数据库中已存在的类型设置

2. **自动初始化**: 遍历所有默认类型,如果数据库中不存在,自动创建记录并保存

3. **空值处理**: 如果数据库记录存在但`values`为空,使用默认值

4. **日志输出**: 添加控制台日志,便于调试和确认初始化过程

5. **数据持久化**: 确保所有类型设置都持久化到数据库,避免重启后丢失
