# 权限系统使用说明

## 功能概述

本系统实现了基于多角色的权限管理，主要特点：
1. **灵活的角色管理**：管理员可以自由创建和配置角色
2. **多角色支持**：员工可以被分配多个角色
3. **权限并集**：员工的最终权限是所有角色权限的并集
4. **细粒度控制**：支持对每个模块的增删改查导权限进行独立配置

## 一、角色管理

### 1.1 新增角色

1. 进入"系统设置" > "角色权限"标签
2. 点击右上角"新增角色"按钮
3. 填写角色信息：
   - **角色标识**（必填）：用于程序识别，建议使用小写英文+下划线，如 `sales_manager`
   - **角色名称**（必填）：显示名称，如"销售经理"
   - **角色描述**（可选）：描述角色的职责和权限范围
4. 配置功能权限：
   - 对每个模块（任务、商机、项目、目标、个人信息）配置权限
   - 可配置的权限类型：查看、创建、编辑、删除、导出
5. 点击"创建角色"保存

### 1.2 编辑角色

1. 在角色列表中找到要编辑的角色
2. 点击"编辑权限"按钮
3. 修改角色名称、描述或权限配置
4. 点击"保存权限"

**注意**：角色标识创建后不可修改

### 1.3 默认角色

系统预置了三个默认角色：
- **管理员（admin）**：拥有所有权限
- **经理（manager）**：可管理本部门及下级数据，但不能删除
- **员工（employee）**：可管理自己的数据和协作数据，权限较少

## 二、员工角色分配

### 2.1 为员工分配角色

1. 进入"系统设置" > "员工管理"标签
2. 找到要编辑的员工，点击"编辑"按钮
3. 在"角色（可多选）"区域：
   - 勾选要分配给该员工的角色（可多选）
   - 取消勾选要移除的角色
4. 点击"保存修改"

### 2.2 查看员工角色

在员工列表的"角色"列可以看到员工被分配的所有角色。

## 三、权限计算规则

### 3.1 功能权限（并集）

员工的最终功能权限 = 所有角色权限的**并集**

**示例**：
- 员工A被分配了"销售专员"和"项目助理"两个角色
- 销售专员：商机管理（查看✓、创建✓、编辑✗、删除✗）
- 项目助理：项目管理（查看✓、创建✗、编辑✓、删除✗）
- 最终权限：
  - 商机管理：查看✓、创建✓、编辑✗、删除✗
  - 项目管理：查看✓、创建✗、编辑✓、删除✗

**计算逻辑**：
```
只要任一角色拥有某个权限，该员工就拥有该权限
最终权限 = 角色1权限 OR 角色2权限 OR ... OR 角色N权限
```

### 3.2 数据权限（自动应用）

数据权限规则**自动应用**，无需配置：
1. **自己创建的数据**：可增删改查
2. **协作人数据**：可查看和编辑（任务、商机、项目的协作人）
3. **下级数据**：可查看所有下级及下级的下级的数据
4. **同部门公开数据**：可查看同部门成员设为公开的数据

## 四、在代码中使用权限

### 4.1 使用 Hook

```typescript
import { usePermissions } from '../hooks/usePermissions';

function MyComponent() {
  const { userPermissions, checkPermission, loading } = usePermissions(currentUser);
  
  // 检查某个权限
  const canCreateTask = checkPermission('task', 'create');
  const canDeleteOpportunity = checkPermission('opportunity', 'delete');
  
  // 根据权限显示/隐藏按钮
  return (
    <div>
      {canCreateTask && <button>创建任务</button>}
      {canDeleteOpportunity && <button>删除商机</button>}
    </div>
  );
}
```

### 4.2 使用工具函数

```typescript
import { getUserPermissions, hasPermission } from '../utils/permissionUtils';

// 获取用户的完整权限
const permissions = getUserPermissions(currentUser, rolePermissions);

// 检查单个权限
const canEdit = hasPermission(currentUser, rolePermissions, 'project', 'edit');
```

## 五、最佳实践

### 5.1 角色设计建议

1. **按职能划分**：根据实际业务职能设计角色（如销售、市场、项目管理）
2. **避免过细**：不要创建过多相似的角色，增加管理复杂度
3. **权限最小化**：只授予角色必需的权限
4. **明确描述**：为每个角色编写清晰的描述，说明职责范围

### 5.2 员工分配建议

1. **必选角色**：每个员工至少分配一个角色
2. **多角色场景**：
   - 身兼多职的员工（如销售兼项目经理）
   - 需要临时权限的员工（如短期支持其他部门）
3. **定期审查**：定期检查员工的角色分配是否合理

### 5.3 权限管理建议

1. **管理员权限**：谨慎分配管理员角色
2. **删除权限**：删除权限应当特别谨慎授予
3. **导出权限**：涉及敏感数据的模块，导出权限需要严格控制
4. **定期审计**：定期审查角色权限配置，确保符合安全要求

## 六、常见问题

### Q1: 员工没有分配任何角色会怎样？
A: 员工将没有任何功能权限，无法使用系统功能。建议至少为每个员工分配一个基础角色。

### Q2: 如何临时给员工增加权限？
A: 创建一个临时角色（如"临时审批权限"），分配给该员工，使用完后移除即可。

### Q3: 角色标识可以修改吗？
A: 角色标识创建后不可修改，因为它被用作程序中的唯一标识。如需修改，请创建新角色并迁移员工。

### Q4: 如何撤销某个员工的所有权限？
A: 在员工编辑界面，取消勾选所有角色，或将员工状态设为"暂停使用"或"离职"。

### Q5: 数据权限规则可以自定义吗？
A: 目前数据权限规则是固定的，自动根据创建人、协作人、上下级关系、部门关系计算。如有特殊需求，需要在代码层面进行定制。
