# 权限管理系统说明

## 概述

本系统实现了完整的权限管理机制，包括**功能权限**和**数据权限**两个维度。

## 一、功能权限

功能权限由角色决定，控制用户能够使用哪些功能模块和操作。

### 1.1 权限配置位置

- 路径：系统设置 → 角色权限管理
- 默认角色：
  - **管理员（admin）**：拥有所有权限
  - **经理（manager）**：除删除外的所有权限
  - **员工（employee）**：基本查看和创建权限

### 1.2 权限操作类型

每个模块（任务、商机、项目、目标、账户）包含以下操作权限：

| 操作 | 说明 |
|-----|------|
| 查看 | 可以查看模块数据（受数据权限规则限制） |
| 创建 | 可以创建新数据 |
| 编辑 | 可以编辑有权限的数据 |
| 删除 | 可以删除数据 |
| 导出 | 可以导出数据 |

### 1.3 如何配置功能权限

1. 进入"系统设置" → "角色权限管理"
2. 点击角色卡片上的"编辑权限"按钮
3. 在弹出的对话框中，勾选或取消勾选对应模块的操作权限
4. 点击"保存权限"完成配置

## 二、数据权限

数据权限自动应用，控制用户能够访问哪些具体数据。

### 2.1 数据权限规则

系统按照以下优先级自动判断数据访问权限：

#### 规则1：自己创建的数据
- **权限**：完整的增删改查权限
- **说明**：用户对自己创建的数据拥有全部操作权限

#### 规则2：协作数据
- **权限**：查看 + 编辑
- **说明**：作为任务/商机/项目的协作人，可以查看和编辑该数据
- **适用场景**：
  - 任务协作人：在任务中被添加为协同人
  - 商机协作人：在商机中被添加为协作人
  - 项目协作人：在项目中被添加为协作人

#### 规则3：下级数据
- **权限**：查看
- **说明**：可以查看所有下级（包括下级的下级）的数据
- **判断依据**：通过员工管理中的"上级"字段建立的上下级关系
- **示例**：
  ```
  经理A
    └── 员工B
        └── 员工C
  
  经理A 可以查看 员工B 和 员工C 的所有数据
  员工B 可以查看 员工C 的数据
  ```

#### 规则4：同部门公开数据
- **权限**：查看
- **说明**：可以查看同部门成员设为公开的数据
- **前提条件**：
  1. 数据所有者与当前用户在同一部门
  2. 数据的"公开"开关设置为开启

#### 规则5：全局公开数据
- **权限**：查看
- **说明**：所有人都可以查看标记为公开的数据
- **前提条件**：数据的"公开"开关设置为开启

### 2.2 权限判断流程

```
查询数据时 → 系统自动构建查询条件：
  ↓
  条件1: 自己创建的 (ownerId = 当前用户ID)
  或
  条件2: 作为协作人 (collaborators 包含当前用户ID)
  或
  条件3: 下级创建的 (ownerId 在下级列表中)
  或
  条件4: 同部门公开的 (ownerId在同部门 且 isPublic = true)
  ↓
  返回符合条件的数据
```

### 2.3 数据权限示例

假设：
- 用户A（经理）：市场部
- 用户B（员工）：市场部，上级是用户A
- 用户C（员工）：销售部

**场景1：任务权限**
- 用户A创建任务T1（公开）→ A可增删改查，B和C可查看
- 用户B创建任务T2（私密）→ B可增删改查，A可查看（上级），C不可见
- 用户C创建任务T3（私密），添加B为协作人 → C可增删改查，B可查看和编辑，A不可见

**场景2：商机权限**
- 用户B创建商机O1（公开）→ B可增删改查，A可查看（上级+同部门），C可查看（公开）
- 用户C创建商机O2（私密）→ C可增删改查，A和B不可见

## 三、使用权限工具函数

系统提供了完整的权限工具函数（位于 `/utils/permission.ts`），方便在代码中进行权限判断。

### 3.1 导入工具函数

```typescript
import { 
  buildQueryConditions,    // 构建查询条件
  checkDataPermission,     // 检查数据权限
  canView,                 // 判断是否可查看
  canEdit,                 // 判断是否可编辑
  canDelete,               // 判断是否可删除
  getUserFunctionPermissions,  // 获取功能权限
  checkFunctionPermission      // 检查功能权限
} from '../utils/permission';
```

### 3.2 查询数据时应用权限

```typescript
// 在加载数据时
const loadTasks = async () => {
  const currentUserId = '...'; // 当前用户ID
  const currentUserRole = '...'; // 当前用户角色
  
  // 1. 构建权限过滤条件
  const queryConditions = await buildQueryConditions(
    currentUserId, 
    currentUserRole, 
    db
  );
  
  // 2. 应用到查询中
  const result = await db.collection('tasks')
    .where({
      isDeleted: false,
      ...queryConditions  // 自动应用权限过滤
    })
    .get();
    
  // 返回的数据已经按权限过滤
  setTasks(result.data);
};
```

### 3.3 检查单条数据的权限

```typescript
// 判断用户对某条数据的权限
const permissions = await checkDataPermission(
  currentUserId,           // 当前用户ID
  task.owner,             // 数据所有者ID
  task.collaborators,     // 协作人ID列表
  task.isPublic,         // 是否公开
  db                     // 数据库实例
);

// 判断具体操作权限
if (canView(permissions)) {
  // 可以查看
}

if (canEdit(permissions)) {
  // 可以编辑
}

if (canDelete(permissions)) {
  // 可以删除
}
```

### 3.4 检查功能权限

```typescript
// 获取用户的功能权限
const permissions = await getUserFunctionPermissions(userId, db);

// 检查是否有某个模块的某个操作权限
if (checkFunctionPermission(permissions, 'task', 'create')) {
  // 用户有创建任务的权限
  renderCreateButton();
}

if (checkFunctionPermission(permissions, 'opportunity', 'delete')) {
  // 用户有删除商机的权限
  renderDeleteButton();
}
```

## 四、数据库集合说明

**数据结构：**
```json

  "role": "employee",        // 角色标识（admin, manager, employee）
  "name": "员工",            // 角色名称

  "permissions": {
    "task": {
      "view": true,
      "create": true,
      "edit": false,
      "delete": false,
      "export": false

    "opportunity": { ... },
    "project": { ... },
    "goal": { ... },
    "account": { ... }
  },
  "createdAt": "2025-12-13T...",
  "updatedAt": "2025-12-13T..."

```

## 五、前端界面使用

### 5.1 查看角色权限

1. 以管理员身份登录
2. 进入"系统设置"
3. 点击"角色权限管理"标签页
4. 查看各角色的权限配置

### 5.2 编辑角色权限

1. 在角色权限列表中，找到要编辑的角色
2. 点击"编辑权限"按钮
3. 在弹出的对话框中修改权限配置：
   - 勾选/取消勾选对应模块的操作权限
   - 修改角色名称和描述（可选）
4. 点击"保存权限"完成

### 5.3 设置员工上级

1. 进入"系统设置" → "员工管理"
2. 找到要设置的员工，点击"编辑"
3. 在"上级"下拉框中选择该员工的直接上级
4. 点击"保存"

### 5.4 数据公开/私密设置

在创建或编辑任务/商机/项目时：
- 勾选"公开"：同部门成员可查看
- 不勾选"公开"：仅自己、协作人、上级可访问

## 六、常见问题

### Q1: 为什么我看不到某些数据？
**A**: 检查以下几点：
1. 数据是否设置为公开？
2. 你是否是数据的创建者或协作人？
3. 你是否是数据创建者的上级？
4. 你和数据创建者是否在同一部门？

### Q2: 协作人可以删除数据吗？
**A**: 不可以。只有数据的创建者才能删除数据（或管理员）。协作人只有查看和编辑权限。

### Q3: 上级可以编辑下级的数据吗？
**A**: 默认情况下，上级只能查看下级的数据，不能编辑。如果需要编辑，需要被添加为协作人。

### Q4: 如何批量设置数据权限？
**A**: 目前需要逐条设置。后续可以考虑添加批量操作功能。

### Q5: 管理员和普通用户的区别？
**A**: 
- 管理员可以查看和管理所有数据，不受数据权限限制
- 普通用户只能访问有权限的数据

## 七、技术实现要点

### 7.1 性能优化

- **权限缓存**：用户权限信息缓存5分钟，避免频繁查询数据库
- **批量查询**：下级关系使用队列+广度优先搜索，减少数据库查询次数
- **查询优化**：在数据库层面应用权限过滤，而不是查询后再过滤

### 7.2 安全考虑

- 所有数据访问都必须经过权限验证
- 权限规则在服务端（数据库查询层）执行，不依赖前端
- 使用CloudBase数据库的查询条件，而不是前端过滤

### 7.3 扩展性

权限系统设计为可扩展的架构：
- 可以轻松添加新的角色
- 可以为不同模块配置不同的权限粒度
- 数据权限规则可以根据业务需求调整
