# 系统参数功能说明

## 功能概述

在系统设置的"类型设置"中，所有类型选项现在都支持"系统参数"标记。标记为系统参数的选项将**不可编辑**和**不可删除**，以保护系统核心配置。

## 功能特性

### 1. 系统参数标识
- **视觉标识**：系统参数在列表中显示蓝色的"系统参数"徽章
- **按钮状态**：编辑和删除按钮对系统参数显示为灰色禁用状态
- **鼠标提示**：悬停在禁用的按钮上会显示"系统参数不可编辑"或"系统参数不可删除"的提示

### 2. 保护机制
- **UI层保护**：系统参数的编辑和删除按钮被禁用，无法点击
- **逻辑层保护**：即使绕过UI，后端逻辑也会检查并拒绝对系统参数的编辑和删除操作
- **提示信息**：尝试编辑或删除系统参数时会弹出明确的提示信息

### 3. 数据结构

**TypeItem 接口：**
```typescript
interface TypeItem {
  value: string;       // 选项值
  enabled: boolean;    // 是否启用
  isSystem?: boolean;  // 是否为系统参数（true=不可编辑删除）
}
```

## 用户自定义参数

用户通过"+ 新增"按钮添加的新选项：
- **不是系统参数**（`isSystem: false`）
- **可以编辑**：可以修改选项名称
- **可以删除**：在未被引用的情况下可以删除

## 使用场景

### 场景1：尝试编辑系统参数
1. 打开系统设置 → 类型设置
2. 找到带有"系统参数"徽章的选项
3. 点击"编辑"按钮（已禁用，无法点击）
4. 如果强制触发编辑，会弹出提示："系统参数不能编辑！"

### 场景2：尝试删除系统参数
1. 打开系统设置 → 类型设置
2. 找到带有"系统参数"徽章的选项
3. 点击"删除"按钮（已禁用，无法点击）
4. 如果强制触发删除，会弹出提示："系统参数不能删除！"

### 场景3：添加自定义参数
1. 点击类型设置块右上角的"+ 新增"按钮
2. 输入新的选项名称
3. 点击"添加"按钮
4. 新添加的选项**不会**标记为系统参数
5. 可以正常编辑和删除（未被引用时）

### 场景4：启用/禁用参数
- **系统参数和自定义参数都可以启用/禁用**
- 禁用的参数在下拉选择中不会显示
- 但已使用该参数的记录仍然有效

## 数据兼容性

### 旧数据自动升级
系统会自动识别旧格式数据并升级：
- **旧格式**：`string[]`（字符串数组）
- **新格式**：`TypeItem[]`（对象数组，包含 value、enabled、isSystem）

**升级逻辑：**
- 如果选项值在默认值列表中 → 标记为系统参数（`isSystem: true`）
- 如果选项值不在默认值列表中 → 标记为自定义参数（`isSystem: false`）

### 示例

**旧数据：**
```json
{
  "type": "task",
  "values": ["日常工作", "商机跟进", "项目任务", "客户定制"]
}
```

**自动升级后：**
```json
{
  "type": "task",
  "values": [
    { "value": "日常工作", "enabled": true, "isSystem": true },
    { "value": "商机跟进", "enabled": true, "isSystem": true },
    { "value": "项目任务", "enabled": true, "isSystem": true },
    { "value": "客户定制", "enabled": true, "isSystem": false }
  ]
}
```

## 技术实现

### 1. 数据模型
```typescript
interface TypeItem {
  value: string;
  enabled: boolean;
  isSystem?: boolean;
}
```

### 2. 数据加载
- 支持旧格式（字符串数组）和新格式（对象数组）
- 自动识别系统默认值并标记
- 确保所有数据都有 `isSystem` 属性

### 3. UI渲染
- 系统参数显示蓝色徽章
- 编辑和删除按钮根据 `isSystem` 状态禁用
- 提供清晰的鼠标悬停提示

### 4. 保护机制
- UI层：按钮禁用
- 逻辑层：函数开始时检查 `isSystem` 属性
- 双重保护确保系统参数不被误操作

## 注意事项

1. **系统参数可以禁用但不能删除**
   - 禁用后在新建时不会显示
   - 但不影响已有记录

2. **自定义参数删除需满足条件**
   - 没有任何记录引用该参数
   - 否则会提示无法删除

3. **数据迁移**
   - 系统会自动识别并升级旧数据
   - 无需手动操作

4. **保存机制**
   - 修改后需点击右上角"保存所有设置"按钮
   - 按钮会根据是否有修改自动启用/禁用

## 常见问题

### Q1: 如何知道哪些是系统参数？
A: 系统参数会显示蓝色的"系统参数"徽章，且编辑和删除按钮为灰色禁用状态。

### Q2: 为什么系统参数不能编辑？
A: 系统参数是系统核心配置，与业务流程紧密关联。修改可能会影响系统稳定性和数据完整性。

### Q3: 可以将自定义参数改为系统参数吗？
A: 目前不支持在UI中修改。如有需要，需要直接修改数据库。

### Q4: 系统参数可以禁用吗？
A: 可以。禁用后不会在新建记录时显示，但不影响已有记录。

### Q5: 删除自定义参数后已有记录怎么办？
A: 系统会检查引用，如果有记录使用该参数，会拒绝删除并提示修改相关记录。
