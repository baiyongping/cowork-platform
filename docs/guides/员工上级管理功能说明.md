# 员工上级管理功能说明

## 功能概述

在系统设置的"员工管理"模块中新增了"上级"管理功能，支持为每个员工设置其直属上级，用于建立组织内的汇报关系。

## 功能特性

### 1. 上级列表显示

在员工管理列表中，新增了"上级"列，显示每个员工的直属上级姓名：

| 字段 | 说明 |
|-----|------|
| 用户名 | 员工的登录用户名 |
| 姓名 | 员工的真实姓名 |
| 手机号 | 员工的联系电话 |
| 部门 | 员工所属部门（可多个） |
| **上级** | **员工的直属上级姓名（新增）** |
| 角色 | 员工的系统角色 |
| 状态 | 员工的在职状态 |
| 操作 | 编辑/删除操作 |

### 2. 编辑上级信息

点击员工列表中的"编辑"按钮，在弹出的编辑模态框中，可以设置该员工的直属上级：

#### 上级选择下拉框

- **位置**：在"部门"和"角色"字段之间
- **功能**：从下拉列表中选择该员工的直属上级
- **选项**：
  - "无上级"：表示该员工没有直属上级（如CEO、总经理等）
  - 所有其他员工的列表（排除自己）
- **显示格式**：`姓名 (部门)` 例如：`张三 (销售部)`
- **说明文字**：选择该员工的直属上级，用于汇报关系管理

### 3. 数据存储

- **字段名**：`supervisorId`
- **数据类型**：字符串（员工的 `_id`）
- **存储位置**：`users` 集合
- **默认值**：空字符串或 `null`（表示无上级）

## 使用场景

### 1. 组织架构管理

通过设置上级关系，可以清晰地展示公司的组织架构和汇报关系：

```
总经理
├── 销售总监
│   ├── 销售经理A
│   │   ├── 销售员1
│   │   └── 销售员2
│   └── 销售经理B
│       ├── 销售员3
│       └── 销售员4
└── 技术总监
    ├── 开发经理
    │   ├── 程序员1
    │   └── 程序员2
    └── 测试经理
        └── 测试员1
```

### 2. 任务审批流程

当任务需要审批时，可以根据上级关系自动确定审批人：
- 员工提交任务 → 自动发送给直属上级审批
- 直属上级审批后 → 继续上报给上级的上级

### 3. 权限控制

根据上级关系实现数据权限控制：
- 员工可以查看自己的数据
- 上级可以查看下属的数据
- 管理员可以查看所有数据

### 4. 绩效考核

在绩效考核系统中：
- 直属上级负责评估下属的工作表现
- 上级的上级进行复核
- 跨级评估需要特殊权限

## 操作步骤

### 设置员工上级

1. 登录系统（管理员账号）
2. 进入"系统设置" → "员工管理"
3. 找到要设置上级的员工，点击"编辑"按钮
4. 在弹出的编辑框中，找到"直属上级"下拉框
5. 从下拉列表中选择该员工的直属上级
6. 点击"保存"按钮

### 取消员工上级

1. 进入员工编辑界面
2. 在"直属上级"下拉框中选择"无上级"
3. 点击"保存"按钮

### 查看组织关系

1. 在员工管理列表中，"上级"列显示每个员工的直属上级
2. 可以通过上级信息快速了解组织结构
3. 结合部门信息，全面掌握人员配置

## 数据结构

### users 集合新增字段

```typescript
{
  _id: string,              // 员工ID
  username: string,         // 用户名
  name: string,            // 姓名
  phone: string,           // 手机号

  status: string,          // 状态
  supervisorId: string,    // 直属上级ID（新增）
  createdAt: Date,         // 创建时间
  updatedAt: Date          // 更新时间
}
```

### 查询示例

**查询某员工的直属上级**：
```typescript
const employee = await db.collection('users').doc(employeeId).get();
const supervisorId = employee.data.supervisorId;

if (supervisorId) {
  const supervisor = await db.collection('users').doc(supervisorId).get();
  console.log('上级姓名:', supervisor.data.name);
}
```

**查询某员工的所有下属**：
```typescript
const subordinates = await db.collection('users')
  .where({
    supervisorId: employeeId,
    approvalStatus: 'approved'
  })
  .get();

console.log('下属列表:', subordinates.data);
```

**查询整个汇报链**：
```typescript
async function getReportingChain(employeeId: string) {
  const chain = [];
  let currentId = employeeId;
  
  while (currentId) {
    const emp = await db.collection('users').doc(currentId).get();
    if (!emp.data) break;
    
    chain.push({
      id: emp.data._id,
      name: emp.data.name,
      role: emp.data.role
    });
    
    currentId = emp.data.supervisorId;
  }
  
  return chain;
}
```

## 注意事项

### 1. 防止循环引用

❌ **错误示例**：
- A 的上级是 B
- B 的上级是 C
- C 的上级是 A（形成循环）

✅ **正确做法**：
- 在设置上级时，系统会自动排除当前员工
- 建议在实际使用中，手动检查是否存在循环引用

### 2. 上级变更影响

当某员工的上级发生变更时，可能会影响：
- 待处理的审批流程
- 正在进行的任务分配
- 现有的权限设置

建议：在变更上级前，先处理完该员工的所有待办事项。

### 3. 离职员工处理

当某员工离职（状态改为"离职"）后：
- 该员工作为上级的记录不会自动清除
- 建议在员工离职前，先将其下属重新分配给其他上级
- 或在离职后，批量更新其下属的上级关系

### 4. 权限说明

- 只有**管理员**可以设置员工的上级关系
- **普通用户**只能查看自己的上级信息
- 所有员工都可以在员工列表中看到其他员工的上级

## 技术实现细节

### 1. 数据加载优化

```typescript
// 一次性加载所有员工，然后在内存中匹配上级关系
const employeesWithSupervisor = employeesWithDept.map((emp: any) => {
  if (emp.supervisorId) {
    const supervisor = employeesWithDept.find((e: any) => e._id === emp.supervisorId);
    return {
      ...emp,
      supervisorName: supervisor ? supervisor.name : '未知'
    };
  }
  return {
    ...emp,
    supervisorName: '-'
  };
});
```
