# 离职人员数据交接功能说明

## 功能概述

当员工离职时，系统会自动将其数据权限转移给指定的交接对象，确保业务连续性。

## 核心功能

### 1. 交接对象选择
- **触发条件**：在员工详情页面，将状态改为"离职"
- **选择范围**：只能选择状态为"在职"的员工
- **必填项**：离职时必须选择交接对象

### 2. 数据权限转移
转移的数据范围包括：
- ✅ **任务** (tasks)
- ✅ **商机** (opportunities)
- ✅ **项目** (projects)

转移的权限包括：
- ✅ **owner**（负责人）：将离职员工负责的数据转移给交接对象
- ✅ **collaborators**（协同人）：将离职员工替换为交接对象

### 3. 登录限制
- ✅ **完全禁止登录**：离职用户无法再登录系统
- ✅ **登录提示**："账号已离职，无法登录系统"

### 4. 签名标记
- ✅ **显示格式**：`用户名 (已离职)`
- ✅ **适用范围**：所有显示用户名的地方（目前已在任务列表中实现）

### 5. 操作确认
- ✅ **二次确认弹窗**：执行数据交接前需要用户明确确认
- ✅ **详细说明**：弹窗中列出所有即将执行的操作

## 操作流程

### 管理员操作步骤

1. **进入员工详情**
   - 在"系统设置 > 员工管理"中点击要离职的员工
   - 点击"编辑"按钮

2. **设置离职状态**
   - 将"状态"改为"离职"
   - 系统自动显示"交接对象"选择器

3. **选择交接对象**
   - 从下拉列表中选择接收数据的员工（只显示在职员工）
   - 查看提示信息："⚠️ 离职后，该用户的任务、商机、项目数据将转移给交接对象"

4. **确认交接**
   - 点击"保存"按钮
   - 系统弹出确认对话框，显示详细操作说明：
     - 将XXX的状态设置为"离职"
     - 转移数据权限给：XXX
     - 包括：任务、商机、项目的负责人和协同人权限
     - 离职用户将无法再登录系统
     - 所有操作将被记录到操作日志
   
5. **执行交接**
   - 点击"确认交接"
   - 系统自动执行数据转移
   - 显示交接完成提示

## 技术实现

### 后端云函数

**云函数名称**：`handover-data`

**功能**：
```javascript
{
  fromUserId: '离职用户ID',
  toUserId: '交接对象ID',
  leftAt: '离职时间'
}
```

**执行逻辑**：
1. 验证参数和交接对象状态
2. 更新离职用户状态（status='离职', handoverTo, leftAt）
3. 批量更新数据集合（tasks, opportunities, projects）
   - 转移owner权限
   - 替换collaborators中的离职用户
4. 记录操作日志
5. 记录交接历史（用于可能的回滚）

**返回结果**：
```javascript
{
  success: true,
  message: '数据交接成功',
  transferResults: [
    { collection: 'tasks', ownerTransferred: 5, collaboratorTransferred: 3 },
    { collection: 'opportunities', ownerTransferred: 2, collaboratorTransferred: 1 },
    { collection: 'projects', ownerTransferred: 1, collaboratorTransferred: 0 }
  ]
}
```

## 安全保障

### 1. 数据完整性
- ✅ 使用事务批量更新，确保数据一致性
- ✅ 记录详细的交接历史，支持审计
- ✅ 交接前验证交接对象状态

### 2. 操作安全
- ✅ 二次确认机制，防止误操作
- ✅ 只有在职员工可以作为交接对象
- ✅ 离职状态变更和数据转移原子性执行

### 3. 日志记录
- ✅ operation_logs：记录离职和交接操作
- ✅ handover_history：记录转移的数据详情
- ✅ 包含转移数量统计

## 使用场景示例

### 场景1：销售人员离职

**背景**：销售A离职，负责5个商机、3个项目，由销售B接手

**操作步骤**：
1. 管理员打开销售A的员工详情
2. 状态改为"离职"
3. 交接对象选择"销售B"
4. 点击保存，确认交接
5. 系统自动：
   - 销售A状态变为"离职"
   - 5个商机的owner从销售A改为销售B
   - 3个项目的owner从销售A改为销售B
   - 销售A参与的协同任务中，协同人替换为销售B

**结果**：
- ✅ 销售B继承所有销售A的业务数据
- ✅ 销售A无法再登录系统
- ✅ 所有列表中，销售A的名字显示为"销售A (已离职)"

### 场景2：项目经理离职

**背景**：项目经理C离职，由项目经理D接手

**操作步骤**：同上

**特殊情况**：如果项目经理C同时是某些任务的协同人，系统会自动将这些任务的协同人列表中的C替换为D

## 注意事项

1. **离职操作不可逆**：一旦设置为离职并保存，用户将无法登录，数据权限已转移
2. **交接对象选择**：务必确认交接对象正确，系统不支持重新分配
3. **数据访问**：离职后，原用户无法访问任何数据，即使通过API也不行
4. **历史记录**：离职用户的历史操作记录（createdBy/updatedBy）仍保留，不会改变
