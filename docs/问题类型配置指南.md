# 问题类型配置指南

## 配置说明

问题管理功能从系统设置中的`type_settings`集合读取问题类型、状态和优先级配置。这样可以让管理员灵活自定义这些分类。

### 步骤1: 打开CloudBase控制台

访问: https://tcb.cloud.tencent.com/dev?envId=cowork-9gg9oocb516be5fb#/db/doc

### 步骤2: 找到type_settings集合

在文档型数据库中,找到`type_settings`集合。

## 自定义配置

配置完成后,可以在"系统设置 → 状态设置"页面中:

### 添加新类型

1. 进入对应的类型设置(问题类型/状态/优先级)
2. 点击"添加类型"
3. 输入类型名称和标签
4. 保存

### 修改类型

1. 找到要修改的类型
2. 点击编辑
3. 修改名称或标签
4. 保存

### 禁用类型

1. 找到要禁用的类型
2. 切换"启用"开关为关闭状态
3. 保存

注意: 禁用的类型不会在创建问题时显示,但已有问题的类型不会改变。

## 字段说明

### type (必填)

类型标识符,用于程序识别配置类型:
- `issueType`: 问题类型
- `issueStatus`: 问题状态
- `issuePriority`: 问题优先级

### name (必填)

配置的显示名称,用于界面展示。

### description (选填)

配置的描述信息,说明此配置的用途。

### values (必填)

类型值数组,每个值包含:

- `value` (必填): 类型的实际值,存储在问题记录中
- `label` (必填): 类型的显示标签,在界面上展示
- `enabled` (必填): 是否启用,false时不在选择器中显示
- `color` (选填): 颜色代码,用于优先级等需要颜色标识的类型

### createdAt / updatedAt (必填)

创建和更新时间,使用CloudBase的日期格式:

```json
{ "$date": "2025-12-28T10:00:00.000Z" }
```

## 验证配置

配置完成后,可以通过以下方式验证:

### 1. 检查数据库

在CloudBase控制台的`type_settings`集合中,应该看到3条记录:
- issueType
- issueStatus
- issuePriority

### 2. 检查前端

1. 打开问题管理页面
2. 点击"新建问题"
3. 检查类型选择器中是否显示配置的类型
4. 检查状态选择器中是否显示配置的状态

### 3. 检查筛选

在问题列表页面:
1. 类型筛选下拉框应显示配置的类型
2. 可以正常筛选不同类型的问题

## 常见问题

### Q: 配置后前端不显示?

A: 尝试以下步骤:
1. 刷新浏览器(Ctrl + F5强制刷新)
2. 检查浏览器控制台是否有错误
3. 确认配置的字段名和格式正确
4. 检查`enabled`字段是否为`true`

### Q: 可以删除某个类型吗?

A: 建议不要直接删除,而是将`enabled`设为`false`禁用。如果已有问题使用了该类型,删除会导致数据异常。

### Q: 如何调整类型显示顺序?

A: 在`values`数组中调整元素的顺序即可,前端会按照数组顺序显示。

### Q: 可以添加子类型吗?

A: 当前版本不支持层级分类,如果需要可以使用"-"或"/"分隔,例如:
- "技术问题-数据库"
- "技术问题-前端"

## 默认配置

如果没有配置,系统会使用以下默认值:

### 问题类型默认值
```javascript
['技术问题', '流程问题', '资源问题', '沟通问题', '其他']
```

### 问题状态默认值
```javascript
['未开始', '进行中', '已完成', '延期', '取消', '暂停']
```

但是**强烈建议**在数据库中配置,这样管理员可以根据实际需求灵活调整。

## 总结

通过`type_settings`集合管理问题类型配置,实现了:

1. **灵活配置**: 管理员可以根据实际需求自定义类型
2. **动态加载**: 前端自动从数据库读取最新配置
3. **统一管理**: 所有类型配置在一个集合中集中管理
4. **易于扩展**: 可以方便地添加新的配置类型

这种设计使得问题管理功能能够适应不同企业的实际需求,而不需要修改代码。
