# 际华协同办公平台 - 开发规范

## 核心开发规则（必须严格遵守）

### 1. 报告创建规则
- ❌ **禁止**在每个任务完成后自动创建完成报告
- ✅ 只在所有任务完成后创建一个统一的完成报告
- ✅ 只在命令行输出简单的任务完成状态
- 📝 报告命名：`项目模块_版本_完成报告.md`

### 2. 构建部署规则
- ❌ **禁止**未经用户明确指令进行构建或部署
- ✅ 所有构建和部署操作必须等待用户明确指令
- ⚠️ 不询问是否需要部署，等待用户主动下达部署指令
- 🔧 示例：等待用户说"请部署到测试环境"或"请构建"

### 3. 工具优先规则
- ✅ 优先使用CloudBase工具和Lighthouse MCP工具
- ❌ 减少使用命令行直接操作
- 📌 工具优势：已集成认证、自动处理配置、更安全

### 4. 需求确认规则
- ✅ 开发前必须确认需求和实现方案
- ✅ 向用户确认理解是否正确
- ❌ 不要在未确认的情况下直接开始开发

### 5. 全局检查规则
- ✅ 发现bug时，全局检查是否有相同问题
- ✅ 一次性修复所有相同的bug
- 📌 避免只修复单点问题，遗漏其他地方

### 6. 规则复习规则
- ✅ 每日开始工作前复习这些规则
- ✅ 确保理解并遵守所有规范
- 📖 规则是指导方针，不是限制

### 7. UI交互规则（新增）
- ✅ 保存/更新操作 → **移除**确认窗口（直接保存）
- ✅ 删除操作 → **保留/添加**确认窗口（防止误删）
- 📌 用户体验原则：
  - 保存频繁且可逆 → 无需确认
  - 删除不可逆且危险 → 必须确认

## 确认窗口使用规范

### 需要确认的操作（保留confirm）
```typescript
// ✅ 删除操作
if (!confirm('确定要删除吗？')) return;

// ✅ 不可逆的关键操作
if (!confirm('此操作不可撤销，确定继续吗？')) return;
```

### 不需要确认的操作（移除confirm/alert）
```typescript
// ❌ 不要在保存时确认
// alert('保存成功'); // 移除

// ❌ 不要在更新时确认  
// alert('更新成功'); // 移除

// ✅ 直接保存，静默成功
await db.collection('xxx').update(data);
```

## 异常情况

以下情况可以创建报告/执行操作：
- 用户明确要求创建报告
- 用户明确要求构建或部署
- 紧急修复需要立即部署
- 任务间隔时间很长（跨天），可以阶段性总结
